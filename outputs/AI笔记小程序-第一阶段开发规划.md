# AI 芋泥笔记微信小程序：第一阶段开发规划

## 执行版：范围、架构与验收

本节取代下文历史初稿的执行口径。当前 v3 高保真原型是功能和交互验收基准；首发不包含录音卡，不开发绑定、通信或文件回传，也不增加小程序内录音。首发通过导入已有音频生成笔记。其他原型功能逐项映射到 M1–M5；若不能首发实现，必须在范围台账记录原因、后续批次和验收条件，不得默默删减。浏览器打印等依赖 Web 的能力按用户目标验收，小程序实现方式在 M0 定案。

沿用微信原生小程序 + TypeScript + 微信云开发 + 阿里云百炼。前端按课程、采集、笔记和学习模块组织，页面通过模块服务使用统一的数据契约；云端先做身份与归属校验、课程课时写入、文件存储和异步处理。M2 只建课程、课时、源文件所需数据结构；M3 按需引入处理任务、转写片段、笔记及来源引用；M4 在现有笔记结构中保存校正内容；M5 仅在功能需要持久化时新增实体和云函数。首发不建设设备实体、设备适配层或未定义的商业化系统。所有 API Key 仅通过服务端密钥配置注入，禁止进入客户端、提交历史、日志或测试夹具。

| 阶段 | 具体任务与页面 | 接口与 Mock / 真实边界 | 测试与验收门槛 |
|---|---|---|---|
| M0 首发范围确认与工程设计 | 固定 v3 版本，盘点全部路由、入口、返回路径和异常状态；标记设备排除项；确定首发数据、文件约束、接口及验收用例。涉及全部原型页面，无实现。 | 只定义登录、课程课时、文件导入、任务状态、笔记及来源的最小契约；不部署接口，不调用真实服务。 | 走查台账，每个非设备入口都有阶段或明确后续项；核对状态、数据归属和验证样本；评审通过才开始 Spike。 |

| M2 课程、课时与音频导入 | 实现微信身份、课程与课时基础管理、选择音频、校验、上传及归档。涉及登录、首页、课程/课时、导入和录音整理。 | 接真实微信身份、云数据库和云存储；转写与生成仍用 Mock。 | 真机导入有效音频；验证非法文件、取消、上传失败重试、重复提交及跨账户资源隔离。 |

| M5 AI 问答、复习及其他原型功能 | 按台账逐项实现问答与来源、重点和复习清单、思维导图、练习与批阅、导出、图片与课件及其原文、课程组织、示例、消息、我的文件及个人服务等非设备功能。 | 先用 Mock 对齐交互；交付功能接真实持久化与所需百炼、OCR、文档解析、通知或导出接口；只读示例可用固定数据。 | 逐项对照 v3 验证正常与异常路径；验证问答来源、题目评分、资料页定位和账号隔离；任何延期项须明确记录。 |
| M6 测试、修复与上线准备 | 全量回归、真机及弱网测试、缺陷修复、隐私配置与上线检查。涉及全部首发页面。 | 首发业务路径使用真实测试环境；Mock 仅作故障回归。 | 首发核心路径全通过；无阻断缺陷；逐项核对原型台账、部署和回滚说明，通过验收后才提交上线。 |

每次只执行一个阶段，Spike 也作为独立验收关卡。每阶段保留任务清单、测试证据和 Git 提交；未通过验收不进入下一阶段。所有正式交付物归档至用户指定 GitHub 项目仓库；临时抓取文件、原始课堂音频、密钥和缓存不纳入提交。发布和推送只在明确目标仓库后进行。

**第一个可执行任务（M0）**：建立 v3「页面／入口 → 功能 → 首发或后续阶段 → 验收用例」台账。先从本地原型版本记录提交标识，逐页核对；设备入口标记为首发排除，其他入口均须有归属。交付台账及首发音频流程的验收用例，确认无漏项后再开始 Spike。

## 最新范围决定（优先于下文初稿）

- **最终交付以当前 v3 高保真原型为产品验收基准**：对齐用户可见功能、页面入口、跳转、返回和异常状态。下文 P0/P1/P2 用于安排实现顺序，不据此删减最终功能。原型中的固定数据、模拟计时和浏览器专用实现只作参考。PRD 保留为需求追溯依据；与原型冲突处以本次产品确认更新，例如 AI 问答需保留原型的入口和范围选择交互，具体问答规则联调前核对。
- **首发没有录音卡**：主链路为选择已有音频 → 校验并上传 → 归档课时与可选录音整理 → 后台转写与笔记生成 → 查看、编辑及原文定位。首发不提供小程序内录音。录音卡发现、绑定、文件回传及依赖硬件的通知不作为首发交付或验收条件；上线时建议暂不展示对应入口，待硬件具备后按原型补齐，不用模拟硬件替代真实能力。
- **开发顺序**：先按原型实现音频主流程，用 Mock 验收页面和异常交互，再用真实云存储、ASR 与百炼验收上传、转写、生成和溯源。课件、图片及复习等原型功能仍在最终范围内，具体批次未因本次补充而冻结。下文 M7 移出首发路径；M0 不再把硬件协议作为开工前置条件。首发无需建设设备数据表或通信适配层。

> 范围说明：本文仅做需求分析与开发规划，不包含业务代码。功能边界以 PRD 为准；高保真原型只用于补足页面、状态和交互，不将原型中的演示细节自动升级为需求。

## 1. 需求基线与待确认项

### 1.1 产品闭环

课堂内容采集 → AI 转写 → AI 对话 → 结构化笔记 → 编辑校正 → 原文溯源 → 课后复习。

目标用户为在读大学生，优先大一、大二及人文社科学生。产品不是通用录音转写、会议纪要或泛知识管理工具。

### 1.2 开发前必须冻结的口径

1. **采集方式冲突**：PRD 中同时出现“微信小程序、不绑定专用录音硬件”和“根据老板意见采用硬件+软件（硬件已有）”；v3 原型明确为“录音卡 + 导入本地音频”，并明确不调用手机麦克风。本文暂按最新 v3 原型规划录音卡链路，但该决定须产品确认后才进入开发。
2. **课件/图片导入范围**：PRD Prompt 明确提到语音/PPT/图片转文字，v3 原型也包含图片、PDF、Word、PPT；需确认它们是否属于首发 P0，还是后续范围。
3. **复习范围**：PRD 将基础查看与高级复习区分优先级；原型包含重点速览、复习清单、练习、批阅和打印/PDF。需确认首版只做基础查看，还是保留整套原版复习链路。
4. **AI 问答入口 B**：PRD 明确“问答列表”为可选、非 Must；首版建议只保留课时笔记页入口 A。
5. **商业化规则**：PRD 仅确定免费增值方向，未定义价格、扣费时点或套餐；首版不得自行增加购买逻辑。

| 练习页 | 单选、多选、简答 | 复习页 | 提交确认/结果 | 未答、已答、切题、提交确认 |
| 批阅结果页 | 得分、答案、解析、重练 | 练习提交 | 复习/重练/导出 | 客观题结果、简答参考答案 |
| 我的 | 账户、统计、额度、设备、设置 | Tab | 各个人服务页 | 游客/登录、额度正常/不足 |
| 消息中心 | 处理结果和设备提醒 | 首页/我的 | 对应课时/设备 | 未读、已读、空态 |
| 协议/隐私页 | 合规文本 | 登录/关于 | 返回来源 | 加载失败 |

### 3.2 核心跳转关系

```text
冷启动
├─ 登录有效 → 个人首页
└─ 未登录 → 游客首页 ─→ 只读示例课程
                 └─ 写操作 → 登录 → 续接原操作

首页 → 课程详情 → 课时详情
  └→ 添加课堂记录
      ├→ 录音卡文件 → 文件详情 → 回传 → 录音整理
      ├→ 本地音频 → 校验/命名 → 录音整理
      └→ 图片/课件 → 校验/命名
                         ↓
                    转写与生成 → 课时详情/消息通知

课时详情 → AI 笔记 → 编辑校正
                    ├→ 生成依据 → 原文时间点
                    ├→ 原文/转写
                    └→ AI 学习助手 → 来源段落/原文时间点

课时详情 → 复习 → 练习 → 批阅结果
```

## 4. 核心用户流程与验收条件

1. **首次体验**：游客进入 → 查看只读示例 → 触发写操作 → 勾选协议并授权 → 返回原操作。验收：示例数据不进入个人课程，取消登录不丢失来源页。
2. **本地音频生成笔记**：选择课程 → 选择文件 → 格式/大小校验 → 命名课时 → 可选裁剪 → 创建后台任务 → 离页 → 收到完成通知 → 查看笔记。验收：任务和结果严格绑定课时，可失败重试且不重复建课时。
3. **录音卡回传**：绑定设备 → 查看待回传文件 → 文件详情 → 选择课程 → 中断/恢复 → 裁剪 → 生成。验收：中断后设备原文件仍可用，传输可续接或安全重试。
4. **编辑与溯源**：打开笔记 → 编辑/备注 → 对照原文 → 返回仍保留草稿 → 保存 → 查看生成依据 → 跳到时间点。验收：原始转写不被笔记编辑覆盖。
5. **课时 AI 问答**：从笔记进入 → 课时已锁定 → 提问 → 正常回答带来源；越界固定拒答；失败不展示虚假来源。验收：不跨课时、不联网补充。
6. **复习**：查看自动重点 → 加入复习清单 → 标记掌握/移出 → 返回原笔记；若纳入练习，则答题 → 确认提交 → 客观题批阅。

## 5. 微信原生小程序技术架构

### 5.1 总体结构

```text
微信原生小程序（TypeScript）
├─ pages / subpackages：页面与分包
├─ components：纯展示与通用交互组件
├─ services：云函数调用、上传、任务轮询、Mock 适配
├─ stores：登录、课程、课时、上传/任务状态
├─ domain：实体类型、状态机、校验规则
└─ utils：时间、文件、错误映射
        ↓ wx.cloud.callFunction / uploadFile
微信云开发
├─ 云函数：auth、course、lesson、file、aiTask、note、chat、device、notification
├─ 云数据库：业务数据与任务状态
├─ 云存储：音频、图片、课件、导出物
├─ 云托管（可选）：长时任务回调服务
└─ 定时触发器/消息：超时任务补偿、通知
        ↓ 服务端调用（密钥不下发小程序）
阿里云百炼 + ASR/OCR/文档解析服务
```

### 5.2 关键设计

- 小程序端使用原生 `App/Page/Component` + TypeScript；不引入跨端框架。
- 按领域拆分 `account、course、capture、note、review、ai、device`，页面只做编排，业务规则放在 domain/service。
- 使用统一 `ApiResult<T>`、错误码和 Loading/Empty/Error/Content 四态组件。
- AI 采用异步任务：上传完成 → 建任务 → 服务端处理 → 回调/轮询更新 → 通知；禁止小程序请求长时间等待。
- 文件先上传云存储，再由云函数生成短期可访问 URL 交给服务商；百炼密钥只存在云函数环境变量。
- AI 输出采用版本化 JSON Schema；原始输出、解析结果、Prompt 版本和模型版本可追溯。
- 来源关联以 `source_segments` 保存笔记块到转写句/资料页的多对多映射。
- 对硬件协议定义 `DeviceGateway` 接口；Mock 与真实 BLE/Wi-Fi 实现共用调用契约，协议未定前不写死通信细节。
- 数据权限由云函数统一校验 `openid + resource owner`，客户端传入的 ownerId 不作为可信依据。
- 建议分包：主包仅登录、首页、课程；AI 笔记、复习、设备、个人服务放独立分包。

| 结构化笔记 | 固定 Schema 响应 | 阿里云百炼，严格 JSON Schema、超时重试与内容安全 |

| 额度 | 固定剩余次数 | 服务端原子扣减与幂等；付费能力待商业规则确定 |

## 8. 可逐步验收的 Milestone

| 里程碑 | 范围 | 验收门槛 |
|---|---|---|
| M0 需求冻结与工程设计 | 冻结硬件、资料导入、复习、商业化边界；页面路由、Schema、错误码、接口契约 | 待确认项均有书面结论；PRD—页面—接口可追踪 |
| M1 原生小程序骨架与账户 | TS 工程、分包、主题组件、Mock 层、登录/游客/协议/首页导航 | 新老用户分流正确；受限操作登录后可续接 |
| M2 课程与课时 | 课程/课时 CRUD、列表、详情、空态、删除确认 | 数据按用户隔离；删除后返回有效上级页面 |
| M3 采集与任务闭环（Mock AI） | 音频选择、校验、命名、裁剪、上传、任务状态、消息 | 失败可重试；离页后任务状态不丢；不重复创建课时 |
| M4 笔记、原文与编辑 | 结构化笔记、转写、播放器、来源定位、编辑/备注/草稿 | 跨页草稿保留；笔记编辑不覆盖原文；来源可定位 |
| M5 真实 AI 联调 | ASR、百炼结构化生成、Schema 校验、来源对齐、失败补偿 | 用真实课堂样本验收准确性、时延、成本与失败恢复 |
| M6 课时 AI 问答 | 多轮、拒答、来源、课时历史 | 课外问题稳定拒答；正常回答必有有效来源 |
| M7 录音卡联调（条件里程碑） | 绑定、状态、文件列表、回传、中断恢复 | 真机多轮传输成功；断连不丢文件；重复回调幂等 |
| M8 复习与个人服务 | 基础复习；经确认后加入清单、练习、批阅、通知、设置 | 功能逐项按冻结范围验收；不引入未定义付费规则 |
| M9 发布准备 | 隐私合规、内容安全、性能、埋点、监控、灰度 | 真机主流程通过；云函数权限/密钥/告警检查通过 |

建议每个 Milestone 均交付：可运行体验版、验收清单、已知问题、接口/数据变更说明。未通过当前里程碑，不提前堆叠下一阶段功能。

## 9. 第一轮开发建议

确认范围后，首个可运行版本建议只覆盖：登录/游客 → 课程/课时 → 导入音频 → Mock 异步转写与结构化生成 → 查看/编辑笔记 → 原文定位。该切片能最早验证核心价值链，同时不依赖未冻结的硬件协议、真实 AI 效果和商业化规则。
